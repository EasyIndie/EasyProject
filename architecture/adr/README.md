# 架构决策记录（ADR）

> **📋 记录重要的架构决策：为什么这样做，不那样做。**

---

## 什么是 ADR？

ADR（Architecture Decision Record）是一份简短的文档，记录了一次重要的架构决策：

- **上下文**：当时的情况和约束
- **决策**：选择了什么方案
- **后果**：这个选择带来的影响

## 何时创建 ADR

满足以下**任一**条件，就应该创建 ADR：

1. 选择了某个技术方案，有明显的替代方案
2. 决策会影响系统的整体架构
3. 未来可能有人会问"当时为什么这样做"
4. 需要团队达成共识的技术决策

---

## 何时不创建 ADR

- 小的、可逆的选择（选哪个库、哪个命名）
- 遵循已有模式，没有做新决策
- 纯粹的个人偏好（格式化风格等）

---

## ADR 生命周期

```text
proposed → accepted → (deprecated | superseded)
```

- **proposed**：刚提出，还在讨论
- **accepted**：被采纳，正在执行
- **deprecated**：不再适用（但没有替代方案）
- **superseded**：被新的 ADR 取代
