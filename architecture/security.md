# 安全策略

> **🔒 安全设计原则、威胁模型、密钥管理。**

---

## 安全原则

| 原则 | 说明 |
|------|------|
| **最小权限** | 每个组件只拥有完成其工作所需的最小权限 |
| **纵深防御** | 多层防护。一层被突破，还有下一层 |
| **默认安全** | 默认配置是最安全的配置 |
| **不信任输入** | 所有外部输入都需要验证和净化 |
| **不重复造轮子** | 使用经过审计的安全库来做加密和认证 |

---

## 威胁模型

### 常见威胁（OWASP Top 10）

| 威胁 | 缓解措施 |
|------|----------|
| 注入（SQL/XSS） | 参数化查询、输出编码 |
| 认证失效 | JWT 短期有效 + Refresh Token、多因素认证 |
| 敏感数据泄露 | 加密存储、TLS 传输、日志脱敏 |
| XML 外部实体 | 禁用外部实体解析 |
| 访问控制失效 | 服务端权限校验、API 级别鉴权 |
| 安全配置错误 | 安全默认配置、定期审计 |
| CSRF | SameSite Cookie、CSRF Token |
| 使用含已知漏洞的组件 | 依赖扫描、及时更新 |

---

## 密钥管理

- **绝不**在代码或配置文件中硬编码密钥
- 使用环境变量或密钥管理服务（Vault、AWS Secrets Manager）
- 密钥定期轮换
- 不同环境使用不同的密钥

---

## 依赖安全

- CI 流水线中集成依赖扫描
- 发现已知漏洞的依赖 → 立即更新
- 定期审计第三方依赖

---

## AI Agent 特别提示

- **写任何涉及认证/授权的代码时**：重新阅读本文件和 `docs/standards/api.md`
- **处理用户输入时**：默认不信任，验证+净化
- **记录日志时**：检查是否有敏感数据泄露
- **引入新依赖前**：检查是否有已知漏洞
