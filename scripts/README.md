# 脚本（Scripts）

> **🔧 自动化脚本。开发、构建、部署、运维。**

---

## 这是什么？

`scripts/` 存放项目中的自动化脚本。这些脚本不是应用代码的一部分，但它们是项目工具链的重要组成部分。

---

## 目录结构

```
scripts/
├── README.md              ← 你在这里
├── setup.sh                 开发环境初始化
├── build.sh                 构建脚本
├── deploy.sh                部署脚本
├── migrate.sh               数据库迁移
├── seed.sh                  测试数据填充
└── cleanup.sh               清理脚本
```

---

## 脚本规范

每个脚本必须：

| 规范 | 说明 |
|------|------|
| **命名** | `verb-noun.sh` 格式，一眼能看出作用 |
| **Shebang** | `#!/usr/bin/env bash`（或对应的解释器） |
| **帮助** | 支持 `-h` / `--help` 参数 |
| **幂等** | 多次运行结果相同（尽可能） |
| **依赖声明** | 脚本开头注释说明需要的工具 |
| **错误处理** | 使用 `set -e` 或显式错误处理 |
| **文档** | 在脚本头部注释说明用途和用法 |

## 脚本模板

```bash
#!/usr/bin/env bash
# ============================================================
# 脚本名称 — 一句话说明
# ============================================================
# 用途：详细说明脚本做什么
# 用法：bash scripts/verb-noun.sh [options]
# 依赖：git, docker, jq
# ============================================================
set -euo pipefail

show_help() {
  echo "Usage: $0 [options]"
  echo ""
  echo "Options:"
  echo "  -h, --help    显示此帮助"
}

# 脚本主体...
```

## AI Agent 交互指南

1. **重复操作脚本化**：如果某个操作需要执行两次以上，考虑写成脚本
2. **不要为一次性的操作写脚本**：一次性命令放在文档中
3. **使用脚本前**：先阅读脚本头部注释，理解其作用
4. **修改脚本后**：更新头部注释
