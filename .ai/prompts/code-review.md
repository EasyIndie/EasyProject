# 代码审查提示词

---

## 使用说明

将以下提示词发送给 AI Agent，并将 `<placeholder>` 替换为实际内容。

---

## 提示词

```
你是一名代码审查专家。请审查以下代码变更。

## 变更概述
<描述这个 PR 做了什么>

## 关联任务
<任务编号和链接>

## 审查要求

请从以下维度进行审查：

### 1. 功能正确性
- 代码是否实现了预期的功能？
- 是否有遗漏的边界条件？
- 错误处理是否完整？

### 2. 代码质量
- 命名是否清晰有意义？
- 代码是否简洁无冗余？
- 是否遵循了项目的编码标准（见 docs/standards/coding.md）？

### 3. 安全性
- 是否有常见的安全漏洞（注入、XSS、敏感信息泄露）？
- 密钥和敏感数据是否被正确处理？

### 4. 测试
- 是否有对应的测试？
- 测试是否覆盖了主要路径和边界条件？

### 5. 文档
- 公共 API 是否有文档注释？
- 是否需要更新 README 或其他文档？

## 审查标准

遵循项目标准：
- .ai/rules/coding.md — 编码规则
- .ai/rules/documentation.md — 文档规则
- docs/standards/coding.md — 编码标准
- docs/standards/api.md — API 标准（如果涉及 API）

## 输出格式

请输出结构化的审查报告：

### 🔴 阻塞性问题（必须修改才能合并）
（具体指出文件、行号、问题和建议修改方案）

### 🟡 建议改进（建议修改但不阻塞合并）
（具体指出文件、行号、问题和建议修改方案）

### 🟢 做得好
（值得肯定的地方）

### 总结
（整体评价和合并建议）

## 代码变更

<粘贴代码 diff>
```
