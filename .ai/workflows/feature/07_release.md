# Legacy feature workflow: release step

This file is retained for projects that still use the original seven-step feature workflow.

For new work, use the current workflow selector in [../README.md](../README.md):
- [Quick Change](../quick-change.md)
- [Feature Development](../feature-development.md)
- [Major Change](../major-change.md)

Release actions are project-specific. Do not assume every merge requires a version bump, tag, production deployment, or manual task-board movement. Use the project's release policy and obtain explicit human approval for production deployment or irreversible operations.

When linking work to GitHub, use actual issue numbers (for example, `Closes #123`), not local placeholders such as `T001`. GitHub's automatic issue closing syntax requires a real issue reference.
