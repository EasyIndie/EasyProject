# 步骤 5：测试

> **🧪 验证功能正确性。不通过测试的代码不能进入审查。**

---

## 目标

确保功能按预期工作，满足所有验收标准，没有引入回归。

---

## 操作步骤

### 1. 运行现有测试

```bash
make test
```

确保所有已有测试通过。如果有失败：

- 如果是你导致的 → 修复
- 如果是已有的失败 → 记录下来，创建 Fix 任务或 Issue

### 2. 验证验收标准

对照 `specs/<feature-name>/acceptance.md`，逐条验证：

```
验收标准 1: Given X, When Y, Then Z
  → 实际测试: ... ✅/❌

验收标准 2: ...
  → 实际测试: ... ✅/❌
```

### 3. 编写新测试

如果发现以下情况，补充测试：

```
□ 新的代码路径没有测试覆盖
□ 边界条件没有测试（空值、极值、异常）
□ 验收标准中的场景没有自动化测试
```

使用 `.ai/prompts/generate-tests.md` 或调用 QA Agent。

### 4. 运行完整测试套件

```bash
# 单元测试
make test

# 集成测试（如果有）
make test-integration

# 端到端测试（如果有）
make test-e2e
```

### 5. 检查覆盖率

确保新增代码的测试覆盖率符合 `docs/standards/testing.md` 中的要求。

---

## 输出

```markdown
# 测试报告：[功能名称]

## 已有测试
- 总数: N
- 通过: N
- 失败: 0

## 新增测试
| # | 测试名称 | 覆盖场景 | 状态 |
|---|----------|----------|------|
| 1 | should login with valid credentials | 正常登录 | ✅ |
| 2 | should reject invalid password | 错误密码 | ✅ |
| 3 | should lock after 5 failures | 账号锁定 | ✅ |

## 验收标准验证
| 验收标准 | 状态 | 证据 |
|----------|------|------|
| AC-1: 用户可使用邮箱+密码登录 | ✅ | test: should login |
| AC-2: 错误密码提示不泄露信息 | ✅ | test: should reject |

## 覆盖率
- 行覆盖率: XX%
- 分支覆盖率: XX%

## 失败的测试
（如果有，列出失败原因和修复计划）
- 无
```

---

## 如果测试失败

1. **分析失败原因**：是代码 bug 还是测试写错了？
2. **修复代码**（如果是 bug）
3. **重新运行测试**
4. **不要跳过失败的测试**：每个失败都要解决

---

## 检查清单

```
□ 所有已有测试通过
□ 验收标准逐条验证
□ 新代码有测试覆盖
□ 边界条件已测试
□ 异常情况已测试
□ 测试报告已完成
```
