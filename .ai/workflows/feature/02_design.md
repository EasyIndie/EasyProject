# 步骤 2：架构设计

> **🏗️ 设计技术方案。在写代码之前，先确定怎么做。**

---

## 目标

将需求转化为具体的技术方案。确定需要新增、修改哪些组件，数据如何流转，接口如何定义。

---

## 操作步骤

### 1. 理解现有架构

- 阅读 `architecture/system.md` — 系统拓扑
- 阅读 `architecture/adr/` — 已有的架构决策（新的决策不能与已有的冲突）
- 阅读 `.ai/context/architecture.md` — 架构快速概览

### 2. 设计方案

回答以下问题：

| 问题 | 思考方向 |
|------|----------|
| 改哪些组件？ | 新增还是修改现有？ |
| 数据怎么流？ | 从入口到出口的完整路径 |
| 接口怎么定？ | API 的 URL、参数、返回值 |
| 数据怎么存？ | 新表？新字段？新集合？ |
| 依赖是什么？ | 依赖哪些已有的服务或第三方？ |
| 怎么处理失败？ | 每个环节挂了怎么降级？ |

### 3. 考虑关键设计决策

对于重要的技术选择，问自己：

```
□ 有没有更简单的方案？
□ 这个选择以后会不会成为瓶颈？
□ 和项目现有的模式一致吗？
□ 团队成员能理解吗？
```

### 4. 创建 ADR（如果需要）

如果设计决策满足以下**任一**条件，创建 ADR：

- 影响系统架构的重大决策
- 有多种可行方案，需要解释为什么选这个
- 未来可能会质疑"当时为什么这样做"

使用 `.ai/templates/adr-template.md`，放在 `architecture/adr/`。

### 5. 更新 API 文档（如果涉及 API）

如果功能涉及 API 变更，创建/更新 `specs/<feature-name>/api.md`。
