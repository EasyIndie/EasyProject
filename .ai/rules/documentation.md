# 文档规则

> **📜 文档标准。不写文档的代码是不完整的。**

---

## 核心原则

```
如果它没有文档，它就不存在。
If it's not documented, it doesn't exist.
```

---

## 必须文档化的内容

| 内容 | 位置 | 时机 |
|------|------|------|
| **新功能** | `specs/<feature>/prd.md` + 验收标准 | 功能开发前 |
| **架构决策** | `architecture/adr/NNNN-*.md` | 做决策时 |
| **公共 API** | 代码中的文档注释 | 写代码时 |
| **每个目录** | 目录下的 `README.md` | 目录创建时 |
| **部署变更** | `docs/deployment.md` | 发布前 |
| **新依赖** | `.ai/context/tech-stack.md` | 引入时 |

---

## README 标准

每个目录必须有 README.md，包含：

```markdown
# 目录名称

> **一句话：这个目录是什么**

## 这是什么？

## 放什么？

## 不放什么？

## 命名规范

## AI Agent 交互指南

## 相关目录
```

---

## 代码注释

### 必须注释的情况

- **为什么这样做**（当做法不显而易见时）
- **为什么不用另一种做法**（当有常见替代方案时）
- **已知的局限或 TODO**（关联 Issue 编号）

### 不必注释的情况

- **显而易见的代码**：`// 将用户保存到数据库`（代码本身已经说明了）
- **每个字段**：`// 用户名`（`username` 字段本身已经说明了）
- **版本历史**：这是 Git 的工作

---

## 文档更新时机

| 触发事件 | 需要更新的文档 |
|----------|----------------|
| 新功能上线 | `specs/` 标记为完成、`faq.md` |
| API 变更 | `docs/api.md`、代码注释 |
| 架构调整 | `architecture/system.md`、ADR |
| 新依赖 | `.ai/context/tech-stack.md` |
| 流程变更 | `.ai/workflows/`、`.ai/rules/` |

---

## AI Agent 特别提示

- **写完代码后**：立即更新相关文档，不要"之后再说"
- **文档也要 review**：文档变更是 PR 的一部分
- **不要过度文档化**：README + 代码注释 + ADR 覆盖了 90% 的需求
- **文档位置要对**：部署文档不在 architecture 里，需求文档不在 docs 里
