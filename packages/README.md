# 包（Packages）

> **📦 共享库与模块。复用代码，避免重复。**

---

## 这是什么？

`packages/` 存放多个应用共享的代码库。当你发现自己在多个应用中复制粘贴同样的逻辑时，就应该把它提取到一个 Package 中。

---

## 目录结构

```
packages/
├── README.md              ← 你在这里
├── shared/                  通用工具包
├── config/                  共享配置
├── logger/                  日志库
├── auth/                    认证/鉴权库
├── db/                      数据库客户端
└── ui/                      UI 组件库
```

---

## 命名规范

- 使用 kebab-case
- 名称描述库的职责，而非技术实现
- 示例：`auth/` 而非 `jwt-library/`；`db/` 而非 `postgres-client/`

---

## 每个包的标准 README 格式

```markdown
# 包名称

## 用途（Purpose）
这个包做什么？

## API 表面（Public API）
对外暴露的接口、函数、类

## 使用示例（Usage）
最小可运行示例

## 依赖（Dependencies）
外部依赖和版本要求
```

---

## 包设计原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 一个包只做一件事 |
| **显式 API** | 对外暴露的接口明确且稳定 |
| **版本管理** | 包的变更应该能追溯到版本号 |
| **文档齐全** | README 中必须有使用示例 |

---

## AI Agent 交互指南

1. **写新工具函数前**：检查 `packages/` 中是否已有类似功能
2. **发现代码重复时**：提取到 `packages/` 中
3. **使用包时**：阅读包的 README，了解 API
4. **修改包时**：确保所有依赖该包的应用仍然正常运行
5. **包之间依赖**：保持层级清晰，避免循环依赖
