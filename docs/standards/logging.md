# 日志标准

> **📏 日志记录规范。好的日志让你在凌晨 3 点能快速定位问题。**

---

## 日志级别

| 级别 | 含义 | 使用时机 | 示例 |
|------|------|----------|------|
| **ERROR** | 需要立即关注的问题 | 功能异常、数据丢失 | 支付失败、数据库连接断开 |
| **WARN** | 潜在问题或降级 | 接近阈值、重试成功 | API 响应超时但重试成功 |
| **INFO** | 重要的业务流程 | 关键操作、状态变更 | 用户注册、订单创建、服务启动 |
| **DEBUG** | 调试信息 | 开发/排查问题时 | 函数参数、中间计算结果 |
| **TRACE** | 极详细的追踪 | 深度调试 | 每个步骤的耗时 |

---

## 日志格式

使用 **结构化 JSON 日志**：

```json
{
  "timestamp": "2024-01-01T12:00:00.000Z",
  "level": "INFO",
  "message": "用户登录成功",
  "service": "auth-service",
  "trace_id": "abc123-def456",
  "user_id": "user_789",
  "ip": "192.168.1.1",
  "duration_ms": 45
}
```

### 必填字段

| 字段 | 说明 |
|------|------|
| `timestamp` | ISO 8601 格式，UTC 时区 |
| `level` | ERROR/WARN/INFO/DEBUG/TRACE |
| `message` | 人类可读的描述 |
| `service` | 服务/应用名称 |
| `trace_id` | 请求链路追踪 ID |

---

## 日志内容

### ✅ 应该记录

- 关键业务流程（用户注册、下单、支付）
- 外部服务调用（API 请求/响应、耗时）
- 异常和错误（含堆栈）
- 认证/授权事件（登录、权限变更）
- 配置变更

### ❌ 不应该记录

- **密码**：明文密码、Token、密钥
- **个人身份信息（PII）**：身份证号、银行卡号、完整手机号
- **敏感业务数据**：除非脱敏
- **过大的数据**：整个请求体/响应体（除非 DEBUG）

---

## 日志性能

- **不要在热路径上打印 DEBUG 日志**：用条件判断包裹
- **避免字符串拼接**：使用参数化日志 `log.info("user {}", userId)`
- **异步写入**：日志不应该阻塞业务逻辑
- **采样**：高 QPS 场景下对 DEBUG 日志采样

---

## 查询与监控

- 所有 ERROR 日志应触发告警
- 关键流程的 INFO 日志应可在日志平台搜索
- 日志保留期：ERROR 90 天，其他 30 天
