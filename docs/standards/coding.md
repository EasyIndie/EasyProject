# 编码标准

> **📏 所有代码必须遵守此标准。这是代码审查的基准。**

---

## 通用原则

以下原则适用于任何编程语言：

### 1. 可读性

```text
代码被阅读的次数远多于被编写的次数。
写好代码的标准不是"机器能运行"，而是"人能理解"。
```

- 命名清晰，见名知意
- 函数短小，一眼能看到全貌
- 避免深层嵌套（超过 3 层就该重构）
- 垂直分隔：相关代码块之间用空行分隔

### 2. 简洁性

```text
简单是最高级的复杂。
```

- 优先选择朴素的方案
- 不引入不必要的抽象
- 不为了"将来可能需要"预留扩展点
- YAGNI（You Aren't Gonna Need It）

### 3. 一致性

```text
代码库应该看起来像一个人写的。
```

- 遵循项目已有的代码风格
- 使用相同的命名模式
- 统一的错误处理方式
- 统一的文件组织结构

### 4. 防御性

```text
不信任外部输入，不假设调用者总是正确。
```

- 所有外部输入都要验证
- 函数参数做类型和范围检查
- 用断言或显式错误处理保护不变量

## 命名规范

### 通用

| 类别 | 规则 | 好例子 | 坏例子 |
|------|------|--------|--------|
| 变量 | 名词，见名知意 | `userCount` | `cnt`、`u` |
| 函数 | 动词或动词+名词 | `getUser(id)` | `user()` |
| 布尔 | is/has/can 前缀 | `isActive` | `active` |
| 常量 | 全大写蛇形 | `MAX_RETRY` | `maxRetry` |
| 类/接口 | 名词，首字母大写 | `UserService` | `userSvc` |

### 避免

- ❌ 单字母变量（循环中的 `i`、`j` 除外）
- ❌ 缩写（`usrRepo` → `userRepository`）
- ❌ 匈牙利命名法（`strName`、`iCount`）
- ❌ 类型信息在名字中（`userList` → `users`；`userMap` → `userById`）

## 函数设计

### 好函数的特征

```
✅ 单一职责 — 做一件事并做好
✅ 短小 — 通常不超过 30 行
✅ 参数少 — 不超过 4 个
✅ 无副作用 — 不修改传入的参数或全局状态
✅ 返回明确 — 同一个函数不会有时返回数据、有时返回 null
```

### 坏函数的信号

```
❌ 函数名中有 "and" 或 "or" — 做了多件事
❌ 超过 50 行 — 该拆分了
❌ 参数超过 5 个 — 需要封装成对象
❌ Boolean 参数 — 通常意味着应该拆成两个函数
❌ 返回多种类型 — caller 需要做类型判断
```

## 错误处理

- **尽早失败（Fail Fast）**：在参数验证阶段就拒绝无效输入
- **错误信息有用**：包含上下文（什么操作失败了、为什么）
- **不要吞掉异常**：每个 `catch` / `except` 必须有显式的处理
- **不要用异常做流程控制**：异常应该用于异常情况
- **区分可恢复和不可恢复**：重试策略只用于可恢复的错误

---

## 注释

- **解释 Why，不解释 What**：代码说了 What，注释补充 Why
- **不要注释掉的代码**：删除它。Git 历史可以找回
- **TODO 格式**：`// TODO(#Issue号): 描述`
- **公共 API 要有文档注释**：参数的约束、返回值的含义、抛出的异常

---

## 文件组织

- **文件不超过 500 行**：超过就拆分
- **一个文件一个核心概念**：UserService.ts 不应包含 Order 的处理逻辑
- **目录内不超过 15 个文件**：考虑引入子目录
- **文件名描述内容**：`user-authentication.service.ts` 而不是 `service.ts`

## 语言特定指南

### TypeScript / JavaScript

```typescript
// ✅ 使用 const 和 let，不用 var
// ✅ 使用 === 而不是 ==
// ✅ 使用可选链: user?.address?.city
// ✅ 使用解构: const { name, email } = user
// ✅ 使用 async/await 而不是原始 Promise
// ❌ 不使用 any（除非绝对必要且有注释说明原因）
```

### Python

```python
# ✅ 使用类型注解: def get_user(id: int) -> User:
# ✅ 使用 f-string 而不是 % 格式化
# ✅ 使用 context manager: with open(...) as f:
# ✅ 使用列表推导式（保持简洁，不超过一层）
# ❌ 不要使用可变默认参数: def foo(items=[])
```

### Go

```go
// ✅ 显式处理每个 error
// ✅ 使用 defer 管理资源
// ✅ 接口小而精（1-3 个方法）
// ✅ 使用 context.Context 传递
// ❌ 不要使用 panic 做普通错误处理
```

### Rust

```rust
// ✅ 使用 Result 和 Option 而不是 panic
// ✅ 使用 ? 操作符传播错误
// ✅ 使用 RAII 管理资源
// ✅ 遵循 ownership 和 borrowing 规则
// ❌ 不要过度使用 unsafe
```

## 代码审查清单

提交代码前自问：

```
□ 这段代码容易理解吗？
□ 命名精确吗？
□ 有没有更简单的方法？
□ 所有错误都处理了吗？
□ 有遗留的调试代码吗？
□ 有没有魔法数字应该提取？
□ 依赖方向对吗？
□ 文件超过 500 行了吗？
```
