# 需求：健康检查接口

---

## 问题（Problem）

运维团队和监控系统无法快速判断 API 服务是否正常运行。目前只能通过调用业务 API 间接判断，不够直接也不够可靠。

---

## 目标用户（Users）

| 角色 | 需求 |
|------|------|
| DevOps 工程师 | 需要知道服务是否存活，以便在异常时收到告警 |
| 负载均衡器 | 需要健康检查端点来判断是否将流量路由到该实例 |
| 监控系统（Prometheus 等） | 需要采集服务的健康状态指标 |

---

## 解决方案（Solution Overview）

在 API 服务中添加一个 `GET /health` 端点，返回服务的健康状态。当服务正常运行且所有关键依赖（数据库、缓存等）都可用时返回 200，否则返回 503。

---

## 用户故事

- 作为**运维工程师**，我想要一个健康检查接口，以便我能配置监控告警
- 作为**负载均衡器**，我需要一个轻量级的健康检查，以便我能正确地路由流量
- 作为**开发者**，我想要健康检查能反映依赖状态，以便我能快速定位故障

---

## 功能需求

- **FR-001**: 系统必须提供一个 `GET /health` HTTP 端点
- **FR-002**: 当服务和所有关键依赖正常时，返回 HTTP 200 和健康状态 JSON
- **FR-003**: 当任何关键依赖不可用时，返回 HTTP 503 和详细的错误信息
- **FR-004**: 响应必须包含服务运行时间（uptime）
- **FR-005**: 响应必须在 50ms 内完成（P95）

---

## 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | P95 响应时间 < 50ms |
| 安全 | 不需要认证（这是公开端点） |
| 可靠性 | 健康检查自身不应该成为瓶颈 |

---

## 不在范围内（Out of Scope）

- 不包含详细的 SLI/SLO 指标面板
- 不包含 Prometheus metrics 端点（那是另一个功能）
- 不包含自动故障转移

---

## 依赖

| 依赖 | 状态 |
|------|------|
| 数据库连接 | 已有 |
| 缓存（Redis）连接 | 已有（如果项目使用） |
